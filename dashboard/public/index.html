Cross-Site Scripting (XSS)

OWASP A03:2021 — Injection

When a website accidentally runs harmful script code submitted by a user instead of displaying it safely as plain text.

How Cross-Site Scripting (XSS) Works & How to Fix It

▾

In Simple Words (What is it?): Think of a guestbook where people write their names. If someone writes a command like "steal everyone's keys", and the host blindly shouts that command and obeys it, that is what happens in XSS. When a website accepts user input (like a search keyword) and displays it directly on the screen without checking it, an attacker can type code like <img src=x onerror=alert('Hacked')>. The visitor's browser thinks the code came from the website and runs it immediately.

  • Why is it dangerous? The attacker's hidden script can steal login tokens, read private cookies, log whatever the user types, or redirect visitors to fake phishing websites.
  • How do we fix it? Never insert raw user input directly into HTML. Convert special characters (like <, >, ") into harmless text codes, or use safe functions like textContent and sanitizers like DOMPurify so the browser treats the input strictly as text, never as executable code.

SQL Injection (SQLi)

      OWASP A03:2021 — Injection
    

    
When an application pastes user input directly into a database query, allowing an attacker to manipulate the query logic.

  


  

    

      
How SQL Injection Works & How to Fix It

      ▾
    

    

      
In Simple Words (What is it?): Think of a database as a digital filing cabinet, and a login query as asking: "Find the user whose email is Alice AND whose password is correct." In a vulnerable application, user input is pasted directly into that question. An attacker enters ' OR 1=1--. The question becomes: "Find the user whose email is Alice OR where 1 equals 1". Because 1 always equals 1, the database says "Condition met!" and logs the attacker in as Administrator without checking any password.

      
    
        
  • Why is it dangerous? Attackers can bypass authentication to log in as any user or admin, read the entire database of customer records, modify sensitive tables, or delete data.
    • 
        
  • How do we fix it? Use Parameterized Queries (Prepared Statements). The database engine separates the SQL query logic from the user data, ensuring that quotes and commands in user input are treated purely as text data, never as executable SQL instructions.
    •

OS Command Injection (RCE)

      OWASP A03:2021 — Injection
    

    
When an application lets user input trigger unauthorized terminal commands directly on the server computer.

  


  

    

      
How OS Command Injection Works & How to Fix It

      ▾
    

    

      
In Simple Words (What is it?): Imagine an app that lets administrators ping a server by typing an IP address like 127.0.0.1. The server runs that in its background terminal. If the app blindly pastes the text into the terminal without checking it, an attacker can append ; whoami. The server will ping the address and then immediately execute the second command (whoami) on its operating system!

      
    
        
  • Why is it dangerous? This grants direct Remote Code Execution (RCE). An attacker can read confidential server files, install backdoors, download unauthorized scripts, or take complete control over the entire machine.
    • 
        
  • How do we fix it? Never pass user input to a command shell. Strictly check that input only contains valid IP address characters, and use safe function calls with argument arrays (like execFile('ping', [host])) rather than gluing text strings together in a shell.
    • 
      

    

  


  

    

      

        
Attack Vector

        Command Chaining
      


      

        
        
      


      

        
      


      

        

          Injected Shell Execution Output
          
        

        

      

    


    

      

        
Defense & Remediation

        Safe Input Whitelist
      

      
Applies strict input validation: rejects any input containing shell characters (; & | ` $) and uses execFile with argument arrays to prevent shell parsing.

Cross-Site Request Forgery (CSRF)

      OWASP A01:2021 — Broken Access Control
    

    
When an attacker tricks a logged-in user's browser into performing unwanted actions without their knowledge.

  


  

    

      
How Cross-Site Request Forgery (CSRF) Works & How to Fix It

      ▾
    

    

      
In Simple Words (What is it?): Imagine you are logged into your webmail or account in one tab. In another tab, you click a malicious link or visit an attacker's website. That malicious site secretly submits a hidden form saying "update user email to attacker@evil.com". Because your browser already has your active login cookie saved, it automatically attaches the cookie, and the server thinks you approved the change!

      
    
        
  • Why is it dangerous? Attackers can secretly change passwords, update profile emails, transfer funds, or make unauthorized purchases on behalf of the victim.
    • 
        
  • How do we fix it? Use secret Anti-CSRF Tokens. Every sensitive form must include a unique, unpredictable token that only your real website knows. Also configure cookies with SameSite=Lax or Strict so outside sites cannot use them.
    • 
      

    

  


  

    

      

        
Attack Vector

Weak Authentication & Missing Rate Limiting

      OWASP A07:2021 — Identification & Auth
    

    
When a login page lets automated bots guess passwords repeatedly with zero delay or account lockout.

  


  

    

      
How Weak Authentication Works & How to Fix It

      ▾
    

    

      
In Simple Words (What is it?): Imagine a bicycle lock where a thief can try 1,000 combinations every second, and the lock never jams or alerts anyone. Without rate limiting, an automated script can test thousands of common passwords against an account until it finds the right one.

      
    
        
  • Why is it dangerous? Accounts using weak or common passwords can be cracked quickly through automated brute-force attacks, leading to total account takeover.
    • 
        
  • How do we fix it? Add Rate Limiting (e.g. temporarily block or throttle users after 5 failed attempts), enforce strong password requirements, enable Multi-Factor Authentication (MFA), and hash passwords securely using bcrypt or Argon2.
    •

Missing Security Headers

      OWASP A05:2021 — Security Misconfiguration
    

    
When a server omits standard browser safety instructions, leaving users vulnerable to framing tricks like Clickjacking.

  


  

    

      
How Security Headers Work & How to Fix It

      ▾
    

    

      
In Simple Words (What is it?): Every time a browser loads a webpage, the server sends instructions (headers) telling the browser what is safe to do. For example, without the X-Frame-Options header, an attacker can load your website invisibly inside a hidden frame (iframe) on their malicious page. When a user thinks they are clicking a button like "Claim Free Gift", they are actually clicking "Delete Account" on the transparent site underneath. This trick is called Clickjacking.

      
    
        
  • Why is it dangerous? Users can be tricked into performing sensitive actions, browsers can be fooled into running untrusted files, and secure traffic can be downgraded.
    • 
        
  • How do we fix it? Use standard security headers such as Content-Security-Policy (CSP), X-Frame-Options: DENY, and Strict-Transport-Security (HSTS) using standard middleware like helmet.

Nmap Port Scanner & Attack Surface Reconnaissance

      Network Reconnaissance
    

    
Performs real-time TCP port reconnaissance and attack surface discovery against the local test environment (127.0.0.1 / localhost). Identifies listening services, maps open and closed ports, and proves which ports are strictly required to execute each OWASP vulnerability exploit.

  


  

    

      
How Port Scanning & Reconnaissance Works

      ▾
    

    

      
In Simple Words (What is it?): Think of a port scan like checking all doors and windows in a building to see which ones are open. In networking, each service listens on a numbered port (like port 80 for web, port 3000 for app servers). Scanning tells security testers which services are reachable.

      
    
        
  • Target Web Port (Port 3000): The OWASP Juice Shop web application listens on HTTP port 3000. All active application exploits (XSS, SQLi, CMDi, CSRF, Weak Auth, Headers) directly target endpoints on this port.
    • 
        
  • Assessment Controller Port (Port 8080): The EHVA CyberLab dashboard listens on port 8080 to orchestrate payloads, capture telemetry, and test defense mitigations.
    • 
        
  • Closed Ports (21, 22, 80, 443, 3306, 27017): Direct network sockets for FTP, SSH, standard web, and databases are closed. Web exploits operate strictly at HTTP Layer 7 against Port 3000.
